Structural Patterns

Structural design patterns explain how to assemble objects and classes into larger structures, while keeping these structures flexible and efficient. Here we explore two vital patterns: the Adapter, which mends existing incompatibilities, and the Bridge, which prevents future architectural rigidness.

A

The Adapter

"Fixing the past."

Commonly used to make a legacy or third-party class work with your modern interface without changing the source code.

B

The Bridge

"Designing the future."

Designed up-front to decouple an abstraction from its implementation so that the two can vary independently.

Adapter: The Wrapper

In software development, you often find yourself with a library that does exactly what you need, but its interface is "wrong" for your system. The Adapter acts as a middleman that translates your calls into a language the library understands.

Bridge: Decoupling Hierarchies

The Bridge pattern is about avoiding the Class Explosion. Instead of creating a subclass for every combination of features, you split the dimensions into separate hierarchies.

Class Explosion Simulator

Comparing Inheritance vs. Bridge Pattern growth

4

The Exponential Trap

With inheritance, if you have N shapes and M colors, you need N × M classes. Adding 1 shape requires adding M new subclasses.

The Bridge Solution

By using composition, you only need N + M classes. Adding 1 shape only requires adding 1 class to the Shape hierarchy.

Example Case

Building a system with 5 Devices and 4 Remote types.
Inheritance: 20 classes.
